Architecture Principles

The model proposes. The math proves.
LLM suggests hypotheses. Deterministic Python computes geometry.
Separation of concerns:
• Reasoning Agent — generates geological hypotheses
• Retrieval Agent — collects drillhole, geophysics, reports
• Spatial Agent — runs deterministic calculations
• Validation Agent — challenges hypotheses
Trust by design:
• Confidence scores on every output
• Never invents coordinates or grades
• Distinguishes measured vs inferred data

Request Lifecycle

How a geologist's question flows through the system — from hypothesis to validated recommendation.

1
User Input
Geologist asks a question via API or dashboard.
"Where should I drill next at the ABC deposit?"
2
Supervisor — Route & Review
Orchestrator decides: Is this a new task? Does it need planning? Has analysis been done?
Routes to the right agent. Reviews all outputs before returning to user.
Route: Planner Route: Executor Route: Analyst Approve: END
3
Planner — Decompose into Steps
Breaks the objective into 3–6 concrete steps. Each step maps to a specific tool call.
The LLM suggests what to do. The plan is structured, not creative.
plan: [ "Get GPS positions of all drillholes in the area", "Query geological fault data from GIS layers", "Retrieve historical assay results from database", "Calculate optimal drill targets using spatial analysis" ]
4
Executor — Run Tools (Deterministic)
For each step, calls the appropriate tool. Tools return real data, not LLM guesses.
This is where "the math proves" — coordinates, grades, and geometry come from computation.
Core Tools
GIS · DB · Sensors
9
Plugin Tools
Geology · GIS
9
MCP + RAG
External · Knowledge
10
↻ Loops per step until all complete
5
Analyst — Find Patterns & Risks
Receives all tool results. Produces structured analysis with confidence scores.
Does not invent data — only interprets what the tools returned.
analysis: { summary: "Copper grades improve at depth near F1 fault", confidence: 0.78, patterns: ["Grade increases below 150m", "F1 fault controls mineralization"], risks: ["Limited data below 300m"], recommendation: "Drill at intersection of F1 and IP anomaly" }
6
Supervisor — Final Validation
Reviews the analysis. Checks: Are the data sources valid? Is confidence sufficient?
Can loop back to Planner or Executor if more work needed. Max 8 iterations.
APPROVE → Return to user LOOP → More analysis needed
✓
Response with Evidence
Final answer includes: plan, tool results, analysis, confidence score.
Not just "drill here" — but "drill here because these indicators agree."
